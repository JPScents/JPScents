The existing milestone branch and PR hold the frozen contract, evidence, reviews and corrections. ## Authoring, execution and resume

| Entry point or checkpoint                               | Who acts and what happens                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Explicit milestone creation or revision                 | The author reads the approved plan and canonical project rules. Name the approved acceptance criteria, relevant rule and ADR IDs, exclusions, required tests, commands and evidence for affected boundaries. Include `npm run verify` and its PostgreSQL prerequisite. Specify required D2–D4 cases when in scope and the exact focused command where appropriate. Preserve the human Manual Checkpoint and owner approval before writing `Status: Active`. Format the active file before freezing it, since the canonical formatter checks it even when locally Git-ignored. |
| **Run Active Milestone** or **Resume Active Milestone** | The orchestrator follows the existing recovery and PR path. Confirm the owner-approved contract/version, branch, base, dependencies, and remaining review budget. The implementer reads the applicable approved architecture, coding standards, ADRs, baseline and exact exceptions before editing. Escalate new rules, exceptions or material deviations through GOV-01.                                                                                                                                                                                                     |
| Implementation and handoff                              | The implementer runs useful scoped checks while editing. Run the canonical command and all required functional, integration, browser or build checks on the frozen candidate at handoff. Preliminary results may be reused only where identity and boundary match. Use the authorized milestone commit/PR path. A local dirty snapshot can support a trial or interim check. READY on an open PR requires its exact pushed commit and a clean tracked candidate.                                                                                                              |
| Independent review                                      | The orchestrator starts a separate reviewer context with the existing `independent-review` skill. Give it the frozen contract, base, target, changed-file manifest or actual diff, relevant rules/ADRs/exceptions, required evidence and previous findings. Pause implementation changes during review. Require the reviewer to inspect the diff and evidence directly and record the outcome on the same PR when authorized.                                                                                                                                                 |
| Correction and completion                               | CHANGES REQUIRED returns routine findings to the implementer. Rebind applicable checks and independently review the new snapshot. BLOCKED stops advancement until the missing capability or evidence is recovered. ESCALATE sends the owner the decision, recommended option, alternatives and consequences. Apply the existing review budget and preserve the previous findings, evidence and decisions.                                                                                                                                                                     |
| **Sync After Merge**                                    | The existing sync path verifies the human's completed merge and synchronizes the local base. It does not start implementation or review.                                                                                                                                                                                                                                                                                                                                                                                                                                      |

The author and implementer use the approved contracts as the source of truth. Independent review uses the repository protocol. The global workflow's PR transport labels `APPROVE`, `REQUEST_CHANGES` and `NEEDS_DECISION` remain compatible with repository review `PASS`, `CHANGES REQUIRED` and `ESCALATE` respectively. Preserve both the actual reviewer verdict and the workflow's historical record. An older `APPROVE` label alone provides no proof of a snapshot-bound PASS. ## Completion record

Keep the following in the existing PR record, or in the isolated trial handoff when a PR is out of scope:

- Milestone ID, frozen scope and version, owner approval reference, contract digest, and acceptance checklist with evidence.
- Base, target, candidate digest, changed-file/diff identity, and required checks with commands, exits, statuses and exercised boundaries.
- Independent reviewer context ID, reviewed snapshot, verdict and artifact, correction history, outstanding risks and decisions.
- Final outcome **READY**, **CHANGES REQUIRED**, **BLOCKED** or **ESCALATE** and the next action. READY requires every approved criterion satisfied, trustworthy mandatory evidence and a separate PASS on the same candidate, with unresolved blockers cleared. Preserve the human Manual Checkpoint unchecked where applicable.

Run `npm run verify:acceptance` for release and record its aggregate exit. When an approved milestone addresses only some acceptance cases, require passing evidence for the exact in-scope cases and preserve the grouped command's actual FAIL and outstanding cases when it is run. The aggregate command is required to pass when the contract requires the full suite.

Only the owner authorizes material architecture changes, exceptions, destructive operations, merge, hosted protection or deployment. A scoped READY can coexist with a failed release decision. D2–D4 acceptance remains **FAIL**, and promotion stays blocked until the exact release candidate satisfies the full contract. Never treat a passing PR quality job as release authority.
